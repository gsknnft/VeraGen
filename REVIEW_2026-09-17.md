## Outstanding before a public hosted service

1. Project and collection endpoints have no authentication/ownership boundary. Collection GET lists the instance's collections. Anyone with a project ID can access or mutate its data. The README's no-accounts prototype scope explains this but does not provide multi-user isolation. A public source repository is different from a publicly writable hosted instance.
2. Export renders synchronously and has no render concurrency gate or per-user budget. Generation's in-memory IP limiter does not cover export and is not shared between processes.
3. Studio autosaves and deletes optimistically swallow failures; export may read stale server state while debounce timers are pending. Needs acknowledged saves and a flush-before-export path.
4. Live provider integration and complete MP4 export still need end-to-end validation. This pass does not claim successful paid generation or rendered output.
5. README was edited concurrently during this session and currently contains unrelated prebuilt-native/0.3.0 publication claims while package.json is 0.1.0/private. Reconcile those claims before publication. Those concurrent edits were preserved.

## Name

VeraGen better fits the broader studio than Loopface, which describes the initial face-video feature. Keep it provisional, and keep text separate from the hero so renaming is cheap. A quick web check found existing unrelated uses of both names: LoopFace is a Garmin watch face (https://loopface.app/docs/); Veragen is used for prenatal testing (https://veragen.com.ar/ar/). This is not name availability or trademark clearance. No repository rename, domain purchase, publishing or visibility change was made.
